    class Jargon::CLI

    • Jargon::CLI
    • Reference
    • Object

    Overview

    A command-line parser driven by one or more schemas. A CLI is either flat (a single #schema) or in subcommand mode (a map of named #subcommands, each its own Schema or nested CLI). Build one with Jargon.cli/Jargon.new, then #parse arguments into a Result, #json straight to validated data, or #run to also handle --help, completion, and error exits.

    def bare_assignment(enabled : Bool) #

    Control whether a bare key=value token — no leading dashes — may implicitly assign to a named property. On by default. When off, such a token is never read as an assignment: it falls to positional capture if a slot is open, otherwise it is an unexpected argument. Turn it off for deterministic parsing with zero implicit-assignment magic, e.g. when operands legitimately contain = (name=value pairs passed through to another tool) and you never want one silently absorbed as a property. Note that a positional slot already captures =-bearing operands literally regardless of this setting; the switch only governs the implicit-assignment fallback. It does not affect --flag=value, which is standard long-option syntax and always honored. Applies to this CLI and its directly attached Schema subcommands; a nested CLI keeps its own setting. (A colon is never an assignment separator: key:value is always an ordinary token.)

    def config_format(*extensions : String, &block : String -> T) : self forall T #

    Read config files ending in any of extensions with the block, which turns a file's text into anything that can be written as JSON: a TOML library's TOML.parse, say. An added format is looked for ahead of YAML and JSON, and ahead of formats added after it, its extensions in the order given, so where a directory has both app.toml and app.yaml, app.toml takes precedence. Adding yaml, yml, or #json replaces that extension's parser, and it keeps its place.

    cli.config_format("toml") { |text| TOML.parse(text) }
cli.config_format("yaml", "yml") { |text| YAML.parse(text) } # in place of Jargon's YAML reader

    If this invocation is a completion request (the hidden __complete verb), print candidates and — unless exit_process: false — exit 0. Returns true when it handled completion, false otherwise, so it can be called early in a program (before heavy initialization) or as the whole body of a dedicated completion helper binary.     def load_config(*, merge : Bool = true, project : Bool = false) : JSON::Any | Nil #

    Load config from standard locations. Supports YAML (.yaml, .yml) and JSON (.json) files, and any format added with #config_format, which is looked for ahead of them.

    Paths searched (in order):

    1. ./.config/{program_name}.yaml/.yml/.json (project local, flat; project: true only)
    2. ./.config/{program_name}/config.yaml/.yml/.json (project local, directory; project: true only)
    3. $XDG_CONFIG_HOME/{program_name}.yaml/.yml/.json (user global, flat)
    4. $XDG_CONFIG_HOME/{program_name}/config.yaml/.yml/.json (user global, directory)

    Project-local configs are read from the current directory, which may be one someone else controls (a freshly cloned repository), and they would take precedence over the user's own config. So they are off by default; pass project: true to opt in.

    With merge: true (default), merges all configs found (project wins over user). With merge: false, returns first config found. Returns nil if no config file found.

    def parse(args : Array(String) = ARGV, *, defaults : Defaults | Nil = nil) : Result #

    Parse arguments into a Result (parsed data plus any validation errors); never raises on invalid input. defaults seeds values not given on the command line (e.g. from a config file), below CLI args and env vars.

    With subcommands, a mapping in defaults under a subcommand's name is that subcommand's section, and any other key is global. A subcommand takes the global keys it has an option for, then its section's keys over them, every one of them. A nested CLI's section holds its own subcommands' sections the same way.
